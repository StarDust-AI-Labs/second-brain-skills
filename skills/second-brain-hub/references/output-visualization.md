# 工作流步骤链可视化

本规范定义 8 个场景的「步骤链地图卡」用户可见格式。执行步骤与显示映射的唯一事实源是 `route-contracts.json` 的 `progress_map`；本文件只定义格式规则，不重复步骤顺序。

## 第一准则：自主决策自由 + 痕迹强制

系统可自主决定阻塞、降级、跳过、重试，但每一个决策都必须在地图上留下可见痕迹。禁止任何形式的静默处理。该准则优先级高于排版美观。

| 决策 | 地图表现 |
|---|---|
| 阻塞 | `❌` + 阻塞原因 + 给用户的出路（重试/降级/终止），不静默跳步，且不得继续后续步骤 |
| 降级 | `✅` + 痕迹注明「(降级：用 XX 替代，原因)」，透明告知 |
| 跳过 | `⤳ 已跳过` + 契约跳过证据（对应 `optional_steps_skipped`） |

## 状态图标（每步一个，克制使用）

- `✅` 已完成 → 后面跟该步留下的关键痕迹/产出
- `▶` 进行中 → 后面跟 `← 进行中`
- `⬜` 未开始
- `❌` 阻塞 / `⤳` 跳过

emoji 克制规则：状态图标保留（✅▶⬜❌⤳ 是核心视觉语言），去掉装饰性 emoji。每步仅一个状态符号；单卡状态符号数量与当前 `progress_map` 显示步数一致。

## 步骤链地图卡

> 本文件及 `output-cards.md` 中的 ```text 代码块仅为模板示意。在对话中输出卡片时直接以普通文本呈现，不得用代码栅栏（```）包裹卡片内容。

```text
【{场景名}】步骤 {当前}/{总步数}

  ✅ 1 {已完成步骤}     → {关键痕迹}
  ▶ {当前序号} {进行中步骤}     ← 进行中
  ⬜ {后续序号} {未开始步骤}

  痕迹：{当前步留下的可见处理痕迹}
```

- 步骤名、`{总步数}`、顺序取自 `route-contracts.json` 的 `progress_map`。
- `kind: conditional` 的步骤未触发时显示 `⤳ 已跳过` + 跳过证据，不显示为未完成。
- 步骤内部不刷新地图，只在关键步骤边界刷新。

## 四类卡片

- **开始卡**：场景启动时亮出完整地图（全部 ⬜），让用户预知总步骤数。
- **进度卡**：每完成一个关键步骤刷新一次地图，相邻卡片只更新必要状态，不重复长痕迹。
- **完成卡**：全部 ✅，痕迹替换为最终交付物 + 位置 + 下一步。只读/诊断场景省略「位置」。
- **决策卡**：需用户选择时，地图暂停在当前步，下方挂【需要你决定 / 我的建议 / 可选项】。

## 节奏与 token 预算

- 进度卡只在步骤边界刷新。
- 单场景全程地图卡 ≤ 步骤数 + 2（开始 + 完成）。
- 单张地图卡 ≤ 400 字符；单场景所有地图卡累计 ≤ 2000 字符。
- 步骤数控制在 4–7 步；progress_map 显示步少于 4 的场景（如诊断）保持精简，不强行凑步。

## 边界情况

- 步骤失败/门控阻塞：当前步 `❌`，痕迹写阻塞原因，地图停住，决策卡引导用户，不静默跳步，不继续后续步骤。
- 安全降级：该步 `✅` 但痕迹注明「(降级：用 XX 替代)」。
- 条件步骤跳过：标记 `⤳ 已跳过` + 跳过证据。
- onboarding 首次引导：不套场景地图，沿用 onboarding 自己的引导卡，避免两套可视化打架。
- 系统诊断（只读）：地图正常显示，但完成卡省略「位置」。
- 步骤回退/追问：不刷新地图刷屏，只在原地图基础上更新当前步状态。
